# CODEX-Visium Image Registration Pipeline 202606

Compact three-step rerun pipeline for registering Visium HD outputs into CODEX image space.

## Layout

- `1_image_registration.py`: local interactive landmark selection. Writes reusable point JSON files.
- `2_file_transfer.sh`: syncs this pipeline and landmark files to BigPurple.
- `3_online_parallel_overlay_transform.py`: cluster-side parallel transform of H&E image, cell coordinates, matrix copy, overlay, and metadata.
- `comp_table`: master 5-column path table (cluster paths); drives `0_download_from_comp_table.*` and is the single file to edit per new sample.
- `sample_table.data.tsv`: 4-column local (`./data`) table for steps 1 and 3; auto-generated by `0_download_from_comp_table.*`. On the cluster, pass `comp_table` directly (step 3 ignores its 5th column).

## Input Table

Create a TSV with one sample per line:

```text
sample_name	visium_path	codex_reference_tif	codex_channel
NYU658	/path/to/sample_root_or_segmented_outputs	/path/to/reference.tif	34
```

`visium_path` can be either the sample root containing `segmented_outputs/` or the `segmented_outputs/` directory itself.

## Step 1: Local Landmark Selection

Run locally where the images are visible:

```bash
cd /Volumes/hua_mac/research/aris/harvey/spatial_202506/img_reg_202606
python 1_image_registration.py --sample-table sample_table.data.tsv --points-dir points --channel 34
```

This writes:

```text
points/<sample>_points.json
```

The JSON stores full-resolution landmark coordinates, pixel spacing, selected CODEX channel, and source/reference image paths for provenance.

## Local Self-Contained Run (no cluster needed)

All inputs are copied under `data/` and a matching table `sample_table.data.tsv`
uses relative `data/...` paths, so step 3 can run entirely on the Mac:

```bash
cd /Volumes/hua_mac/research/aris/harvey/spatial_202506/img_reg_202606
conda run -n scell python 3_online_parallel_overlay_transform.py \
  --sample-table sample_table.data.tsv \
  --points-dir points \
  --out-dir registered \
  --workers 3
```

`data/` and `registered/` are excluded from `2_file_transfer.sh` so they are not
pushed to the cluster (the cluster reads from its own `/gpfs` paths).

## Step 2: Transfer Pipeline to Cluster

```bash
cd /Volumes/hua_mac/research/aris/harvey/spatial_202506/img_reg_202606
bash 2_file_transfer.sh
```

Default remote target:

```text
/gpfs/data/tsirigoslab/home/zhouh05/harvey/202507/img_reg_202606
```

On the cluster, `comp_table` already holds the correct `/gpfs` paths, so use it directly as the sample table (step 3 reads its first four columns and ignores the 5th).

## Step 3: Online Parallel Transform and Overlay

On BigPurple:

```bash
cd /gpfs/data/tsirigoslab/home/zhouh05/harvey/202507/img_reg_202606
python 3_online_parallel_overlay_transform.py \
  --sample-table comp_table \
  --points-dir points \
  --out-dir registered \
  --workers 6
```

Outputs per sample:

```text
registered/<sample>_registered/
  cell_segmentations.geojson
  filtered_feature_cell_matrix.h5
  overlay.png
  overlay_comparison.png
  README.md
  spatial/tissue_hires_image.png
  spatial/transformation_info.json
```

## Transform Direction

This pipeline transforms Visium HD H&E and Visium cell polygons into CODEX-scaled image space. The overlay uses magenta for CODEX and green for transformed Visium.
